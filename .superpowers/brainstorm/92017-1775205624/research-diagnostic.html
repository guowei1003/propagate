从代码和接口里确认到的诊断

现状问题

  • 导航、表单、卡片全部同权重，首屏没有主次。
  • 空数据时几乎只剩壳子，第一印象单薄。
  • 运行监控和详情页大量直接输出 JSON，缺少专业译码层。
  • 状态没有形成稳定色彩和组件语义，执行门禁看不出来。
  • 页面更像临时后台，而不是 AI 指挥台。

可保留基础

  • 路由壳层已经够简单，适合彻底重组信息架构。
  • 任务、运行、能力、环境、产物五块业务边界清晰。
  • 后端已经返回状态、事件、依赖、产物等核心数据。
  • 旧模板里已有状态标签、进度条、事件流等成熟表达经验。
已确认的产品本质

Propagate V2 不是“展示型仪表盘”，而是“AI 执行编排指挥台”

主线 1：任务编排

创建任务、补充澄清、跟踪执行阶段和子任务依赖。

主线 2：能力审批

审批 agent / skill 候选能力，决定 run 是否能继续推进。

主线 3：交付审计

查看事件、产物、bundle 和最终报告，完成复盘与交付。

真实状态流
界面必须把这些状态翻译成人能快速扫描的信息
WAITING_USER_INPUT → WAITING_APPROVAL → RUNNING / SUBTASK_RUNNING → COMPLETED / PARTIAL_SUCCESS
NEEDS_HUMAN_REVIEW BLOCKED_BY_DEPENDENCY PENDING / READY
